卡密商城 · 原型

8 个页面，前台 4 屏购买链路 + 我的卡密，后台 3 页。全部为静态原型，数据写死在 assets/data.js，交互只做到「能看懂」为止，没有后端。

主流程（建议按顺序点）

1 · 商城首页
分类侧栏 + 商品网格，库存只显示「充足 / 仅剩 N 张 / 售罄」
index.html
2 · 商品详情
质保条压在购买按钮之上，虚拟商品免责声明常显
goods.html?id=1
3 · 确认订单
15 分钟倒计时真跑，与锁库存同一时钟
checkout.html
4 · 卡密交付
首次完整展示，点「模拟再次访问」立刻脱敏
deliver.html

用户中心

我的卡密
已过期的卡密永久脱敏且不可复制，这是防泄露的最后一道闸
my-cards.html
API 平台（对照）
切换过去看两条产品线如何各自拥有独立侧栏与钱包
api-platform.html

商家后台

商品管理
成本与毛利率仅后台可见，毛利率低于 25% 标红
admin-goods.html
卡密库存
列表永久脱敏；点「批量导入」看导入弹窗与判重提示
admin-stock.html
订单管理
含「已支付待补货」告警——这类订单不能拒付
admin-orders.html

原型里刻意做出来的判断

库存不暴露精确数字 → 精确库存等于公开进货量，竞品和上游都会用来压价
质保条在购买按钮上方 → 买家点购买前唯一想确认的就是「坏了赔不赔」
免责声明常显不折叠 → 虚拟商品不退换是法律上的前置告知义务
卡密二次访问即脱敏 → 首次交付页可下载 txt，之后只剩 7f3a****e05b
两个钱包不互通 → API 额度 $ 与商城钱包 ¥ 分开，退款对账口径才清晰
