## 环境与方法

- 后端：本地编译的单二进制，SQLite 全新库，`CRITICAL_RATE_LIMIT=100000`，
  工作目录隔离在 `/tmp/apiduo-e2e`（不污染仓库）
- 上游：`mock-upstream.js` 模拟三种协议
  - chat：SSE（带 `usage`）与非流式 JSON
  - images：返回 `b64_json`
  - video：`/v1/videos` 任务状态机（queued → in_progress → completed）
- 前端：`rsbuild dev`（proxy 到后端），puppeteer 驱动真实 Chrome
- 脚本：`docs/apiduo/e2e/{env,mock-upstream,backend-tests}.py|js`、`frontend-tests.js`

复现：

```bash
# 1. 起 mock 与服务
node docs/apiduo/e2e/mock-upstream.js &
PORT=3901 SESSION_SECRET=apiduo-e2e CRITICAL_RATE_LIMIT=100000 ./apiduo &
# 2. 初始化（setup + 登录 + 渠道 + API 令牌）
python3 docs/apiduo/e2e/env.py
# 3. 后端断言
python3 docs/apiduo/e2e/backend-tests.py
# 4. 前端（另起 dev server 后）
node docs/apiduo/e2e/frontend-tests.js
```

## 测试中发现并修复的问题

1. **生图入口拿不到 relay_mode**（后端，严重）
   `/pg/images/generations` 不匹配 distributor 的 `Path2RelayMode`（只认 `/v1` 前缀），
   请求被当作文本处理，报 `expected dto.GeneralOpenAIRequest, got *dto.ImageRequest`。
   修：三个 handler 里显式 `c.Set("relay_mode", ...)`。

2. **视频查询路由挂错中间件组**（后端）
   `GET /pg/video/generations/:id` 挂在带 `Distribute()` 的组里，distributor 会尝试
   解析 GET 的 body 并选渠道。修：查询单独成组，不挂 `Distribute`。

3. **停止生成后不结算**（前端，偶发）
   两个原因叠加：`stopGeneration` 只对 `isAssistantMessagePending`（loading）收尾，
   已进入 `streaming` 的消息不会被终结；且停止时 messages 引用可能不变，
   effect 不重跑。修：非终态一律收尾 + 用 `settleTick` 强制触发一次结算。

4. **视频参数格式不符合协议**（前端）
   传 `size: "720p"` + `duration: 5`（number），任务插件按 `usageSchema` 校验后
   直接判 `plugin_usage_invalid` / `cannot unmarshal number into seconds`。
   修：`size` 用 `1280x720` / `720x1280`，`seconds` 用字符串。

5. **进度条永远 0**（前端）
   上游把进度写成 `"10%"`，`Number("10%")` 得 NaN。修：strip `%` 后再解析，
   并补齐 `NOT_START` 等状态映射。

  金额以日志为准）。
- **多用户/多分组并发**：本轮只测单用户 default 组，未压测。
- **原有 75 个前端单测**：本轮跑过全绿，但未覆盖到新增三模式的交互路径。
