## 测试中发现并修复的问题

1. **生图入口拿不到 relay_mode**（后端，严重）
   `/pg/images/generations` 不匹配 distributor 的 `Path2RelayMode`（只认 `/v1` 前缀），
   请求被当作文本处理，报 `expected dto.GeneralOpenAIRequest, got *dto.ImageRequest`。
   修：三个 handler 里显式 `c.Set("relay_mode", ...)`。

2. **视频查询路由挂错中间件组**（后端）
   `GET /pg/video/generations/:id` 挂在带 `Distribute()` 的组里，distributor 会尝试
   解析 GET 的 body 并选渠道。修：查询单独成组，不挂 `Distribute`。

3. **停止生成后不结算**（前端，偶发）
   两个原因叠加：`stopGeneration` 只对 `isAssistantMessagePending`（loading）收尾，
   已进入 `streaming` 的消息不会被终结；且停止时 messages 引用可能不变，
   effect 不重跑。修：非终态一律收尾 + 用 `settleTick` 强制触发一次结算。

4. **视频参数格式不符合协议**（前端）
   传 `size: "720p"` + `duration: 5`（number），任务插件按 `usageSchema` 校验后
   直接判 `plugin_usage_invalid` / `cannot unmarshal number into seconds`。
   修：`size` 用 `1280x720` / `720x1280`，`seconds` 用字符串。

5. **进度条永远 0**（前端）
   上游把进度写成 `"10%"`，`Number("10%")` 得 NaN。修：strip `%` 后再解析，
   并补齐 `NOT_START` 等状态映射。

## 未覆盖 / 受限

- **视频终态后的结算与出片展示**：依赖真实任务插件与上游，本地只验证到
  `IN_PROGRESS`；单拉长窗口的结果见附。
- **生图真实产出**：mock 返回 1×1 PNG，只验证链路与计费，未验证真实分辨率/转存。
- **刷新后历史消息的金额**：`billingByKey` 仅存内存，刷新即丢（已确认为设计取舍，
  金额以日志为准）。
- **多用户/多分组并发**：本轮只测单用户 default 组，未压测。
- **原有 75 个前端单测**：本轮跑过全绿，但未覆盖到新增三模式的交互路径。

# 动效验收（2026-11-09 追加）

`docs/apiduo/e2e/motion-check.js`，18 项，全部通过。断言基于计算样式与
逐帧采样，不看截图。

## 为什么用弹簧而不是固定时长

固定时长（`transition: 300ms`）回答的是"跑多久"；弹簧回答的是"多快靠近目标"。
差别只在被打断时才显出来：切 tab 切到一半再切回来，弹簧从当前位置反向，固定
时长会跳回 0 % 重跑。这个页面的主要动作（切模式、展开对账单、看金额落定）都
是"用户随时会改主意"的动作，所以内核是弹簧。

三条曲线取自阻尼振子闭式解，采样 35–42 点写进 `linear()`：

| token | ζ | response | 用在哪 |
|---|---|---|---|
| `--apd-ease-settle` | 1.00 | 0.35 s | 默认。临界阻尼，无过冲 |
| `--apd-ease-pop` | 0.78 | 0.42 s | 金额落定的光环，约 2 % 过冲 |
| `--apd-ease-sheet` | 0.80 | 0.30 s | 抽屉（Apple 官方 sheet 参数） |

不支持 `linear()` 的浏览器拿到同性格的 `cubic-bezier`，布局完全一致——
没有任何信息是靠曲线本身传达的。

## 做了什么

| 位置 | 动效 | 目的 |
|---|---|---|
| 模式 tab | 单块指示器按 `offsetLeft/offsetWidth` 位移 | 让三个 tab 读成"一个控件在移动"，而不是三个状态 |
| 工作区 | key 变 → 弹簧进场（y 6px → 0） | 切模式是"同一平面内移动"，不是换页 |
| 消息 | `apd-rise`（520 ms，y 8px + scale .994） | 新消息到达；scale 只 0.6 %，长列表不会"呼吸" |
| 金额 chip | pending → settled 时一次 `apd-halo`（光环扩散 7 px，只播一次） | 这是本页唯一值得庆祝的时刻，但循环播放会变成装饰 |
| 会话累计 | `RollingValue` 上下翻牌 | 数字变化读成"这个变成了那个"，不是两个字符串互换 |
| 对账单 | `height: auto ↔ 0` + `marginTop` 同动，行 26 ms 递进 | 能中途反悔；行序即阅读序 |
| 价格条 | 模型/分组变 → 重挂载进场；折扣徽章一次性高光扫过 | 换参数和"省了多少"各自有反馈 |
| 生图 | shimmer 骨架 → `apd-media-in`（blur 9 px + scale 1.025 解析 550 ms） | 硬切会让 1024 px 图看着"本来就在那儿" |
| 生视频 | 进度条改 motion `width` 弹簧；状态徽章 `apd-nudge` | 每 2 s 一跳的进度，弹过去比瞬移可信 |
| 按钮 | `:active` 立刻 scale .972 | 按下即反馈，不等抬起 |

## 降级

`prefers-reduced-motion` 下所有位移与关键帧关闭、transition 置 `none`，
内容仍然可见（测试断言 `opacity: 1`）；`prefers-reduced-transparency` 关掉
光环与高光；`prefers-contrast: more` 把 shimmer 与滑块描边提亮。

## 顺手修的两处

1. **深色下 tab 滑块像凹陷**：`--background` 在深色比 `bg-muted/60` 更暗，
   填上去是"洞"不是"凸起"。改成向 `--foreground` 抬 10 % 并加 1 px 内描边。
2. **按次计费的对账单列了不存在的行**：生图/生视频模型没有 token 维度，
   原先照搬 token 那套，显示成 `输入 0 / 输出 0 / 倍率 ×0.00`，看着像算错。
   `QuotaBreakdown` 加 `pricingMode`，按次口径只留模型、组倍率、公式、实扣。

# 消息渲染进度条（2026-11-09 追加）

`docs/apiduo/e2e/progress-check.js`，7 项，全绿。

## 不假装知道百分比

流式响应没有总量，任何"37 %"都是编的。这里用的是渐近线：

```
ratio = 1 - e^(-chars / 620)
```

300 字到 38 %，1000 字到 80 %，2000 字到 96 %；生成途中封顶 94 %，
只有真正完成的那一帧才走满 100 %。因此没有 `aria-valuenow`——对读屏
用户来说它是装饰，状态由消息本身表达。

620 是经验值：本项目回复中位数在 400~900 字，取这个数让中位长度走完
约 2/3 到 4/5。

## 三态

| 阶段 | 表现 |
|---|---|
| 首字未到 | 两条不同速度的扫描带（38 % / 26 % 宽，1.45 s / 1.9 s），一条主体一条回声 |
| 收到内容 | 切成确定态：渐变填充 + 右端 7 px 光点，光源随 `apd-breathe` 轻微呼吸 |
| 完成 | 填满 100 % + 整条闪一次（640 ms），660 ms 后高度收为 0 移除 |
| 失败 | 填充不走到头，停在断点，整条转 `--destructive` |

## 两个实现上的坑

1. **不能挂在 `actions` 里**：首 token 到达之前，上游 `PlaygroundMessageContent`
   的 `showMessageContent` 是 false，整块 `actions` 都不渲染，进度条会跟着消失。
   现在挂在消息块外层。
2. **不能固定裁剪截图**：内容一长，进度条随自动滚动下移，固定区域拍不到。
   验收脚本按 `.apd-progress-track` 自身位置裁剪。

## 验收断言

```
P1 首字未到时是扫描带                      hasTrack=true, hasHead=false
P2 有内容后切确定态并出现笔头              hasHead=true, barWidth=18%
P3 进度随内容单调增长                      28 个采样点：4→83
P4 生成途中封顶 94%，只有完成才到 100      growing 阶段 max=71
P5 完成时填满并闪一次                      barWidth=100, done=true
P6 收尾后彻底移除                          hasTrack/hasHead 均 false
P7 无未捕获 JS 错误                        —
```

采样带阶段标记（`done: bool`），否则完成动画 94 → 100 的中间帧会被误判成
"生成途中提前满格"。第一次跑就是这么错的。
