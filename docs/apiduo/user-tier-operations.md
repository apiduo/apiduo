# 用户分层运营方案

> 适用：apiduo（AI API 网关）。客户是开发者与团队，消耗即收入。
> 与 `growth-console.md` 的看板实现对齐：标注「已有」的字段可以直接用，「待补」的需要加数据。
> 版本：2026-11-16

---

## 一、为什么要重做分层

看板现在按 30 天消耗分位切 K/A/B/S 四层。这个切法有三个硬伤：

1. **新客被埋没**。刚注册没消耗，直接落进 B 或 S，但它是最该投入的人群。
2. **价值与风险混在一起**。一个消耗第一但余额只剩 2 天的大客户，和一个消耗中等但很健康的客户，被放进不同层，运营优先级却反了。
3. **无法回答「该不该救」**。同样是沉默，K 层客户值得花 300 块唤醒，B 层客户花 30 块都算浪费。

所以分层要拆成三个正交维度，各回答一个问题：

| 维度 | 回答的问题 | 取值 |
|---|---|---|
| L1 生命周期 | 现在该**说什么** | 新客 / 成长 / 成熟 / 沉默 / 流失 |
| L2 价值 | 该**投多少** | K / A / B |
| L3 健康度 | 该**先救谁** | 正常 / 余额告警 / 事故 / 渐退 |

运营动作 = L1 决定话术，L2 决定预算，L3 决定优先级。

---

## 二、判定规则（可直接用现有字段）

### L1 生命周期

| 阶段 | 判定 | 数据来源 |
|---|---|---|
| 新客 | 注册 ≤ 7 天 | `users.created_at` 已有 |
| 成长 | 注册 8–30 天且有调用 | `created_at` + `last_active_at` 已有 |
| 成熟 | 注册 > 30 天且近 7 天有调用 | 同上 |
| 沉默 | 30 天无成功调用 | `last_active_at` 已有 |
| 流失 | 60 天无成功调用且从未充值 | `last_active_at` + `topup_total` 已有 |

### L2 价值

沿用分位切点，但**只对「有过成功调用」的账户排名**（现在是这么做的，正确）。

| 层 | 规则 | 规模上限 |
|---|---|---|
| K | 活跃账户消耗前 3% | 硬上限 20 人 |
| A | 前 15%（累计） | — |
| B | 其余有调用的活跃账户 | — |

上限 20 是刻意的：K 层的定义是「运营能叫出名字、能打得了电话的账户」，超过这个数就退化成名单。

### L3 健康度（按处置紧迫度排序）

| 优先级 | 类型 | 判据 | 为什么排这个位置 |
|---|---|---|---|
| P0 | 事故型 | 7 天有请求、消耗为 0 | 是我们的责任，不救会变成口碑负资产 |
| P1 | 余额耗尽 | 按近 7 天速率不足 3 天 | 客户还没走，只是快没油了 |
| P2 | 渐退 | 周环比降幅 > 10% | 还有时间窗口 |
| P3 | 沉默 | 30 天无调用 | 窗口已经很窄 |
| P4 | 未激活 | 注册 > 14 天从未成功调用 | 基本是无效注册 |

P0 排第一不是因为它金额最大，而是因为**它的成因在产品侧**。一次上游故障导致的失败，如果不主动说明并补偿，客户会认为是网关不稳定。

## 三、六层 SOP

### N｜新客（注册 0–7 天）

- **目标**：首次成功调用率 ≥ 60%
- **动作**：
  - D0：注册即发「三分钟跑通第一个请求」邮件，含可直接粘贴的 curl
  - D2：未调用则发第二封，附一个真实场景示例（如批量打标、长文档摘要）
  - D6：仍未调用则发第三封，给 5 元体验额度（不是打折，是直接送）
- **权益**：首充加赠 20%，限 7 天内
- **判断**：新客期不看消耗，只看「有没有跑通第一次」

### K｜关键客户（≤20 人）

- **目标**：续约率 ≥ 90%，月消耗环比正增长
- **动作**：每周 1 次 1v1（企微或电话），内容不是推销，是三件事——
  1. 上月用量结构（哪些模型占大头）
  2. 有没有踩到限流或失败
  3. 下月有没有新场景要提前扩容
- **权益**：月消耗的 5–10% 以额度返还，按季度结算
- **禁止**：群发模板消息。K 层收到模板即等于没有触达

### A｜成长客户（前 15%）

- **目标**：升 K 率 ≥ 20%/季度
- **动作**：双周一次，渠道是邮件 + 客户社群。每月发一份用量报告（含同行对比百分位）
- **权益**：3–5% 额度返还
- **判断**：A 层的核心不是维系，是找出「有潜力但没跑满」的账户，给具体场景建议

### B｜普通活跃

- **目标**：月活率 ≥ 70%
- **动作**：全部自动化，不投入人力。产品内提示 + 月度邮件
- **权益**：无
- **判断**：B 层不该有人工触达，人力成本会吃掉全部收益

### R｜风险层（动态，来自预警队列）

按 L3 优先级处置，24 小时内响应：

| 类型 | 动作 | 补偿标准 |
|---|---|---|
| 事故型 | 先解释、再补偿、最后才谈续费 | 按失败请求数折算等额额度 |
| 余额耗尽 | 提醒 + 一次性充值优惠 | 首充加赠 10% |
| 渐退 | 问原因，不要问「还需要什么」 | 无，除非确认是价格因素 |
| 沉默 | 一次性唤醒，不发第二次 | 小额（≤50 元等值） |

### S｜沉睡 / 流失

- **动作**：只发一次唤醒，内容是「产品这半年新增了什么」，不是「我们想你了」
- **判断**：唤醒率低于 8% 就停止投入。反复打扰会损伤品牌，且这批人对价格的敏感度远高于对功能

## 四、预算与 ROI 门槛

**总权益预算 = 上月平台消耗的 3%**，按层分配：

| 层 | 占比 | 理由 |
|---|---|---|
| K | 60% | 集中投在能带来 80% 收入的人身上 |
| A | 25% | 培养下一批 K |
| 风险 | 10% | 止血，不追求回报 |
| 唤醒 | 5% | 期望值本来就低 |

**批次 ROI 门槛：增量消耗 ÷ 权益成本 ≥ 1.5**，低于此值不追加投放。

看板已有批次结算能力，每次发放必须建批次号——没有批次号的发放无法归因，只能算成本。

## 五、运营节奏

| 周期 | 动作 | 耗时 |
|---|---|---|
| 每天 | 过一遍今日队列，P0/P1 当天处理完 | 15 分钟 |
| 每周 | K 层 1v1（每周 5 家，20 家四周轮完） | 2 小时 |
| 每两周 | A 层用量报告 + 邮件 | 1 小时 |
| 每月 | 分层重算、批次结算、写复盘 | 半天 |
| 每季度 | 重新校准分位切点与预算比例 | 半天 |

### 每日队列的处置顺序

不是按时间，是按「损失潜力」：

1. P0 事故型（我们在赔钱，且客户在骂）
2. P1 余额耗尽 + K/A 层（金额大）
3. P1 余额耗尽 + B 层（自动化提醒即可）
4. P2 渐退
5. P3/P4 沉默与未激活

队列长度控制在 10 条以内。超过 10 条说明分层或规则有问题，不是运营不够努力。

## 六、指标

**北极星：月活跃消耗账户数**（有成功调用且消耗 > 0 的账户数）。

选它而不是 GMV，是因为它同时反映「有多少人在用」和「用的人还在」。

| 层 | 核心指标 | 目标 |
|---|---|---|
| 新客 | 7 日激活率 | ≥ 60% |
| K | 季度续约率、月消耗环比 | ≥ 90%、> 0 |
| A | 升 K 率 | ≥ 20%/季度 |
| B | 月活率 | ≥ 70% |
| 风险 | 7 日恢复率 | ≥ 50% |
| 沉默 | 唤醒率 | ≥ 8% |

补充两个健康度指标：

- **集中度**：Top 10 账户消耗占比。超过 50% 说明收入结构脆弱，要主动拓新
- **权益成本率**：发放额度 ÷ 平台消耗。超过 5% 说明补贴失控

---

## 七、避坑

1. **事故没解决前不要做营销触达**。客户正在遭遇失败，你发优惠券等于承认「我知道你出问题了但我不修」。
2. **不要给沉默用户大额补贴**。唤醒率低于 8% 时，大额补贴是纯亏损。
3. **K 层禁止模板化**。一封群发邮件毁掉的关系，十次 1v1 也补不回来。
4. **权益按额度算，不按金额算**。额度成本是边际成本，金额是现金，两者差一个量级。
5. **不要为了指标好看放宽活跃定义**。注册即算活跃，会让所有留存数字虚高，最后没人信看板。

## 八、与看板的差距

| 方案要求 | 看板现状 |
|---|---|
| L1 生命周期（新客/成长/成熟） | **缺**，现在只有沉默/未激活二值判断 |
| L2 价值分层 | 已有 |
| L3 健康度排序 | 已有，但队列按 severity 排，未按「值得救」加权 |
| 新客 7 日激活漏斗 | **缺**，只能事后看单账户 |
| 分群留存曲线（Cohort） | **缺**，只有 7/30 天标量 |
| 触达记录与批次 ROI | 已有 |

要落地这套方案，最小补齐是三件事：**L1 生命周期字段**、**新客激活漏斗**、**Cohort 留存**。
三者都是只读派生数据，不碰转发路径，按现有架构加一张 cohort 表即可。
