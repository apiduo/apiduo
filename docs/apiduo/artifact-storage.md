# 响应产物转存（S3 兼容 / 多云）

apiduo 在 new-api 之上增加了一层**响应改写**：渠道返回结果里如果带着媒体文件（图片地址、
内联 base64、音频数据），网关会把字节复制到自己的对象存储，并把响应里的引用换成存储地址。

默认**关闭**。开关在渠道上，全局只提供存储与默认规则。

## 覆盖范围

| Handler | 覆盖的接口 |
|---|---|
| `image_handler` | `/v1/images/*`（OpenAI 及兼容实现） |
| `compatible_handler` | 所有 OpenAI 兼容接口（火山、Gemini 兼容模式、绝大多数渠道） |
| `claude_handler` | `/v1/messages`（Claude 原生格式） |

流式响应（`text/event-stream`）不处理：它是无限增量的，缓冲它会毁掉流式的意义。

## 三层配置

| 层级 | 位置 | 内容 |
|---|---|---|
| 存储目标 | 系统设置 → 扩展 → 对象存储 | endpoint / bucket / 密钥 / 公开访问前缀，可配多个目标并按序降级 |
| 默认匹配规则 | 同上 | 全局默认的选择器与内置字段名 |
| 渠道规则 | 渠道编辑 → 对象存储 | 勾选启用、可覆盖存储、可覆盖匹配规则 |

优先级：**渠道选择器 > 全局选择器 > 内置字段名**。渠道一旦声明了自己的选择器，就只按它
匹配，不会和全局规则合并——合并会让两条规则同时命中同一个字段，同一份字节被转存两次。

## 匹配语法

### 内置字段名

没配选择器时按字段名匹配，默认集合：

```
url, image_url, audio_url, video_url, file_url, b64, base64, data, audio, audio_data
```

可以在全局配置里换成自己的列表，**不需要改代码**。

`b64_json` **不在默认列表里**。它的契约是「base64 字符串」，把 URL 写进去会破坏所有做解码
的客户端。需要它的渠道用选择器显式声明。

### JSONPath 选择器

每行一个：

```
$.data[*].url                                     就地替换
$.data.0.url                                      固定下标
$.candidates[*].content.parts[*].inlineData.data  Gemini 内联
$.content[*].source.data                          Claude 内联
```

语法：`$` 是根，`.field` 取对象字段，`[*]` 或 `.*` 匹配所有子项，`[0]` 或 `.0` 取固定下标。

### 写到别的字段

对「负载字段」不能就地替换，用箭头形式：

```
$.data[*].b64_json => url         转存后把地址写进同级的 url 字段
$.data[*].b64_json => url clear   写地址，并把原字段清空
```

这样 `b64_json` 的语义不被破坏，同时响应里多了一个可用的链接。

## 写回什么地址

转存后写进响应的是**对象存储自己的地址**，不是网关路径：

- 目标配了 `public_base_url` → `https://cdn.example.com/response/2026/11/07/ab12….png`（永久）
- 没配 → presign 签名 URL（有有效期，是兜底方案）

对象 key 由内容 SHA-256 前 16 字节决定，同一张图返回两次只存一份。

## 支持的存储

全部走 S3 协议，同一套实现：

| 服务商 | Endpoint 示例 | 寻址 | Region |
|---|---|---|---|
| MinIO | `http://minio:9000` | **路径式** | 任意 |
| 阿里云 OSS | `https://s3.oss-cn-hangzhou.aliyuncs.com` | 虚拟主机式 | 必填 |
| 腾讯云 COS | `https://cos.ap-guangzhou.myqcloud.com` | 虚拟主机式 | 必填 |
| 火山引擎 TOS | `https://tos-s3-cn-beijing.volces.com` | 虚拟主机式 | 必填 |

选错寻址方式的表现是 DNS 解析失败或 `SignatureDoesNotMatch`。

## 降级与冷却

多个目标按顺序尝试，第一个成功即止。失败的目标准入冷却：

- 15 秒起，逐次翻倍，上限 5 分钟
- 冷却期间直接跳过，不发起请求
- 一次成功立刻清零

没有冷却的话，一个挂掉的目标会让**每个**请求都先等它超时。

## 安全边界

- **SSRF 防护**：上游返回的地址会解析 DNS 并拒绝环回/私有/链路本地地址，重定向每跳重新
  校验。上游是外部输入，不校验等于给网关开了内网代理。
- 响应体上限 32 MB，单对象上限 64 MB，超了原样透传
- 下载超时 90 秒
- 渠道未启用时零开销：不解析 JSON、不读 body、不发请求

## 网络与代理

存储客户端默认读取 `HTTP_PROXY` / `HTTPS_PROXY`。两个陷阱：

1. **代理会破坏签名**——V4 签名覆盖 Host，代理重写后返回 `SignatureDoesNotMatch`，看起来像密钥错了
2. **内网域名被代理卡住**——很多代理只放行公网

把存储域名加进 `NO_PROXY`（容器里通常还要写小写 `no_proxy`），改完重启。

## 已知边界

- 只处理响应体里的结构化媒体引用。流式响应、二进制直出（如 TTS 直接返回音频流）不处理
- 转存失败不重试：保留原始链接，用户仍能用（前提是上游链接还有效）
- 没有「测试连接」按钮，配置正确性要等第一个响应才能确认
