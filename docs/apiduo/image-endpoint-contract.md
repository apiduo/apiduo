# 图像渠道配置契约（给 agent 读）

> 这份文件的读者是**改这个仓库的 agent**，不是终端用户。
> 目的：避免每次重新推导时把「内部处理」误当成「配置面」。
> 全文只有一条不变量，其余都是它的推论。冲突时以第 1 节为准。

## 0. 一句话

**四个入口折叠成一份 canonical 请求，永远发往主端点；配置面只有一个地址。**

## 1. 不变量（改代码前先确认这四条仍成立）

| 编号 | 必须成立 | 违反后的症状 |
|---|---|---|
| **I1** | 图像渠道的配置面**只有一个**可配置地址：主端点 | 用户要改上游必须改多处，必然漂移 |
| **I2** | `/v1/images/generations`、`/v1/images/edits`、`/v1/chat/completions`、`/v1/responses` 是**四个前门**，只决定怎么读请求、怎么回包 | 被当成四条路由，每条各配一个上游 |
| **I3** | 四个入口的报文差异在**折叠**这一步被抹平，产出一份 canonical 请求；canonical 是中间产物，**不是配置项** | 页面出现「canonical 端点」输入框 |
| **I4** | canonical 之后**永远**发往主端点；协议内部的第二遍处理（如 OpenAI 把带图请求改写成 `edits` + multipart）是**运行时行为**，不占配置面 | 页面出现第二个地址输入框，或「图生图另发」开关 |

推论：`单端点 / 双端点`、`seedream / gpt-image-2`、`上游布局` 这些**都不是用户的选择**，是 I4 的结果。
它们最多能作为只读标签出现，不能是下拉框。

## 2. 判定表

| 入站入口 | 客户端载体 | 折叠后 | 发出 | 处理次数 |
|---|---|---|---|---|
| `/v1/images/generations` | JSON | canonical（`image` 可缺省） | 主端点 | 2（折叠 + 协议编码） |
| `/v1/images/edits` | multipart 文件 part | canonical（图片落成引用） | 主端点 | 2 |
| `/v1/chat/completions` | `messages[]` | canonical（取末轮） | 主端点 | 2 |
| `/v1/responses` | `input[]` / string | canonical（取末轮） | 主端点 | 2 |

「发出」这一列在任何情况下都只有主端点一个值。若实现里出现第二个目标，先回看 I4。

## 3. 主端点的合法形状

- 必须是路径（`/` 开头），不带域名、query、fragment。
- **前缀任意**：`/v1`、`/api/v3`、`/openai/deployments/dalle3`、`/ark/v3` 都合法。
- **末段必须是 `generations`**：这是唯一能确定「这个地址收图片生成请求」的证据。
- 末段不是 `generations`（例如 `/v3/images`）⇒ **拒绝并说明原因，不要猜、不要自动补全**。
- 上游的从端点（OpenAI 的 `edits`）由末段替换推导：`…/generations` → `…/edits`，前缀原样保留；
  推不出来时才是配置项（`image_protocol.edit_path`），且**只出现在高级里**。

## 4. 禁止清单

| 不要做 | 为什么 |
|---|---|
| 给四条入口分别配上游路径 | I2：入口不是路由。这是本仓库历史上最反复的错误 |
| 把 `seedream` / `gpt-image-2` 做成下拉 | 厂商代号不是用户语言；选错不报错，只在第一次图生图时收到上游 4xx |
| 在页面上放「图片协议」开关 | 配了图片主端点就意味着走协议；开关只是把同一件事问两遍 |
| 让 `image_protocol.primary_path` 和 `primary_endpoint` 各填一次 | 同一个值两个输入框，必然不一致 |
| 把 `edit_path` 放在主配置面 | 它是 I4 的逃生阀，默认推导；露出来就会被当成第二个端点 |

## 5. 术语（一个词只指一件事）

- **主端点**：上游真正收图片生成请求的那一个地址。配置面唯一地址。
- **canonical**：四个入口折叠后的那一份请求体。中间产物，不配置、不展示为端点。
- **入口 / 前门**：四个入站路径。只决定读请求与回包形状。
- **第二遍**：canonical 之后按上游协议编码（可能改写路径、换载体）。运行时行为。
- **edit_path**：从端点覆盖，高级项，默认空。

`canonical` 永远不是端点；`主端点` 永远是端点。这两个词混用是本仓库最容易犯的错。

## 6. 改完自检

- [ ] 页面上只有一个地址输入框。
- [ ] 没有「布局 / upstream / seedream / gpt-image-2」这类选择控件。
- [ ] 四个入口没有任何一条能单独指定上游。
- [ ] 主端点末段非法时的提示是「拒绝 + 原因」，不是自动纠正。
- [ ] `edit_path` 只在高级里出现，默认空。
- [ ] 试算能说出「哪个入口 → 折成什么 → 发往哪个地址」三段，而不是只给一个结果。
