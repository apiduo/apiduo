批量生成：失败之后库里到底有几张

P0

两种实现生成同样的 1000 张码，第 137 条注入一个重复 key。 盯住落库行数这一个数字就够了。

旧实现 = 循环单条 INSERT 并各自提交。新实现 = 单事务 + CreateInBatches(100)。

并发兑换同一张码

已具备

50 个请求同时兑换同一张码。故意在读和写之间留出窗口， 对比先读后写与条件更新 CAS 的差别。

CAS = UPDATE ... WHERE status = 1，RowsAffected = 0 即认输。这条已经在线上了。

编辑与兑换竞态

P0

把已兑换的码改回未使用

P0

运营最常见的误操作：想「重置」一张码。旧实现允许， 于是这张码可以再领一次额度。账上就是凭空多出来的钱。

判断依据不是「管理员有没有权限」，而是这笔负债是否已经兑付。
