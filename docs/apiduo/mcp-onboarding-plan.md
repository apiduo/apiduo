# MCP 首次使用体验方案

> 2026-11-14。对象：apiduo.cn 的 MCP 端点（`/mcp`，4 个工具）与后台「MCP 接入 / 能力注册」两页。
> 本文只给方案，不含代码改动。

## 0. 结论

两个问题不是同一件事，但根因相同：**能力与预期都没有被显式表达，Agent 和用户都在猜。**

- **Agent 误判**：不是模型笨，是工具契约留了太多空白（model 可选、参数空 spec、返回值只有 text、错误是纯文本）。修法是**把不确定性在服务端收敛掉**，让 Agent 不需要猜。
- **用户不会用**：不是缺文档，是 MCP 的能力在客户端里不可见。用户配完只看到几个工具名，不知道说什么、也不知道是否连上。修法是**让用户在 3 分钟内成功一次**，用一次真实结果替代所有说明。

不建议做「触发词大全」：MCP 工具由模型自主调用，不需要咒语。真正该给的是**意图模板**（一句话 + 预期结果）。

---

## 1. 诊断：Agent 侧的五个误判点

每一条都有代码或线上数据支撑。

### 1.1 模型选择：留空即取「第一个已启用模型」

`mcp/protocol_tools.go` 的 `pickView` 在 `model` 为空时返回该 kind 下按 id 排序的第一个。工具描述里已经警告「量产站上那通常不是你想要的那个」，但**警告不是约束**——Agent 图省事就不传。

线上日志已出现过这种样本：用户说「flux」，日志记的是另一个模型，事后按模型名搜日志搜不到。

### 1.2 参数：声明了但 Agent 读不懂

`size: {}` 这种空 spec 的语义是「存在、不限值」。Agent 看到空对象，无法判断该传 `1024x1024` 还是 `2K`。目前只能靠 `summary` 里的一句自然语言。

更糟的是工具描述写着「size 取值见 `parameters.size.enum`」——多数模型的 size 根本没有 enum。**描述与数据互相矛盾，Agent 只能猜。**

### 1.3 返回：图生成了，Agent 拿不到图

实测（本次会话，qwen-image-3.0）：

```
text content:        "生成完成（模型 qwen-image-3.0），共 1 个产物"
structuredContent:   outputs[0].url = https://oss.s3ai.cn/...
```

只读 text 的客户端（WorkBuddy 就是）拿不到 URL，Agent 只能回一句「已生成」。为了拿到链接，本次实测不得不重跑一次，多花 $0.01。**这是当前最高频的「假成功」。**

### 1.4 错误：纯文本，Agent 无法分类

`buildPayload` 和上游错误都直接 `fmt.Errorf` 返回字符串。而系统里**已经有一张完整的错误规则表**（`mcp_error_rules`：401 不重试、402 充值、429 退避 3s、5xx 退避 5s、task:FAILED 换参数），`seedGlobalErrorRules` 也建好了默认规则。

**但工具层一次都没用过它。** 结果：Agent 收到「insufficient_user_quota」后仍可能重试；收到「n 不能大于 4」后可能换个措辞继续试同一个值。

### 1.5 能力清单：只有事实，没有判断依据

`models.list` 输出 `id / kind / execution / input / parameters / summary`。全是「这个模型是什么」，没有「我该选哪个」：

- 没有场景标签（写实 / 插画 / 多参考图 / 快）
- 没有成本（flux 固定 $0.2，qwen $0.01，差 20 倍）
- 没有延迟（flux 45s，qwen 96s）

Agent 只能按名字猜，用户只能按价格猜。

## 2. 诊断：用户侧的四个断点

### 2.1 配完没有反馈

「MCP 接入」页（`web/src/features/apiduo-mcp/`）给的是 URL / Header / JSON 三段可复制文本。复制完、粘进 Claude、重启——**然后没有任何信号告诉你成功了**。失败时（令牌删了、URL 少了路径）要等第一次调用才知道。

实测踩到的真实案例：一个 `status=1` 但已软删除的令牌，调用返回 `401 Invalid token`。用户无法从这句判断「令牌被删了」。

### 2.2 不知道怎么开口

用户在 Claude/Cursor 里看到 4 个工具名（`models.list` / `image.generate` / `video.generate` / `task.get`），但不知道：

- 要不要说「调用 image.generate」？（不需要）
- 说「画只猫」够不够？（够，但 Agent 可能不传 model）
- 视频要等多久？会不会超时？

### 2.3 参数无从下手

`size`、`resolution`、`n` 这些词对非技术用户没有意义。而页面目前只讲「怎么连」，不讲「怎么问」。

### 2.4 第一次尝试成本不明确

用户不知道一次生成花多少钱。flux 一次 $0.2，qwen 一次 $0.01，差 20 倍。没有标注，用户不敢试；试错了又觉得被坑。

---

## 3. 设计原则

1. **让 Agent 不需要猜**：能用校验表达的，不用自然语言警告。
2. **一次成功原则**：首次引导只让用户做一件事——出一张图。其余能力第二屏再讲。
3. **失败必须可恢复**：每个错误都要带「下一步做什么」，而不是只解释「哪里错了」。

## 4. 方案 A：协议契约收敛（治 Agent 误判）

### A1. `model` 不做必填，改为结果内引导（2026-11-14 调整）

不传就报错，并在错误里给候选与选择依据：

```json
{
  "error": {
    "code": "MODEL_REQUIRED",
    "message": "必须指定 model。候选：qwen-image-3.0（最快最便宜，1:1 方图）、flux-3-image（写实、多参考图）、doubao-seedream-5-0-flash-260915（方舟档位）",
    "next_action": "call_models_list"
  }
}
```

为什么不是「自动选」：自动选仍会错，且错了没人知道。报错能同时教会 Agent 和用户。

实施口径：曾按「全新功能、不兼容存量」做成硬必填（`MODEL_REQUIRED`），随后推翻。
MCP 的本质是「agent 引导用户做事」，硬门槛把引导变成了拦路——用户说「画张图」，
却被要求先查清单再画，体感是「用不了」。最终方案：不传就回落默认模型，
返回文本里写明「本次用了 X，可选 a b c；下次带上 model 就能指定」，
`structuredContent` 带 `model_defaulted` 供客户端做 UI 提示。

### A2. `models.list` 增加决策字段

```json
{
  "id": "qwen-image-3.0",
  "recommended_for": ["最快", "最便宜", "方图"],
  "cost": {"kind": "per_request", "usd": 0.01},
  "latency": {"p50_ms": 96000},
  "constraints": ["n ≤ 4", "参考图 ≤ 20", "只吃比例，不吃精确像素"]
}
```

`recommended_for` 的取值必须是**用户会说的话**（「快」「便宜」「写实」「多图」），不是模型术语。

### A3. 产物地址进 text

现在：

```
生成完成（模型 qwen-image-3.0），共 1 个产物
```

改成：

```
生成完成（模型 qwen-image-3.0）：https://oss.s3ai.cn/cdn/qwen2api/images/...png
```

多图时每行一个。structuredContent 保持不变。

这是全篇性价比最高的一条：一行字符串拼接，消灭「假成功」。

### A4. 错误结构化，接上已有的规则表

工具层在返回错误前查 `mcp_error_rules`，输出：

```json
{
  "code": "INSUFFICIENT_QUOTA",
  "retryable": false,
  "retry_action": "none",
  "hint": "额度不足，需要充值，重试无用",
  "match": "403"
}
```

同时把「本地校验失败」也纳入同一套码：`PARAM_OUT_OF_RANGE` / `PARAM_NOT_DECLARED` / `MODEL_NOT_FOUND` / `KIND_MISMATCH`。

Agent 拿到 `retry_action` 就不会瞎重试；人看到 `hint` 就知道去哪充值。

### A5. 参数补 examples / note

`ParamSpec` 现在是 `enum / min / max / default`。加两个可选字段：

```json
"size": {"example": "1024x1024", "note": "任意 WxH，仅用于推导画幅比例"}
```

`models.list` 输出后，Agent 看到的是可执行的示例，而不是空对象。

### A6. 工具描述与数据对齐

把 `image.generate` 描述里的「size 取值见 `parameters.size.enum`」改为：

> size 可以不传；传的话，声明里有 enum 就取 enum 内的值，没有 enum 就传 `WxH` 像素或模型声明的档位（如 `1K`/`2K`）。

描述里同时写清「不想选模型就先调 models.list 看 `recommended_for`」。

## 5. 方案 B：首次配置向导（治不会用）

目标：**从打开页面到看见第一张图，3 分钟内完成，只做一个决定。**

### Step 1 · 你是谁（已有）

选客户端。默认高亮两个：Claude Code、Cursor（用户量最大）。其余折叠。

文案不要写「选择你的 MCP 客户端」，写「你在哪里用它？」

### Step 2 · 一键配置（已有，需补一处）

现有三段可复制文本保留。补两点：

- 令牌默认**明文展开**（现在要点选择器才看到），旁边一个「重新生成」。
- 每个客户端给一句「粘到哪里」的路径（已有 `where` 字段，保留）。

### Step 3 · 测试连接（新增，零成本）

一个按钮：**「测试连接」**。

- 服务端复用 `models.list`（不产生生成费用），返回「已连接 · 4 个图片模型 · 2 个视频模型 · 延迟 320ms」。
- 失败按错误码给修法：

| 现象 | 页面提示 |
|---|---|
| 401 | 令牌无效或已删除。点「重新生成令牌」，再替换客户端里的值。 |
| 404 | URL 少了 `/mcp`。当前应为 `https://apiduo.cn/mcp`。 |
| 超时 | 客户端未重启。Claude Desktop / Cursor 改完配置都要重启。 |
| 200 但 0 个模型 | 后台没有启用的能力声明。去「系统设置 → 扩展 → MCP」注册。 |

这一步解决「配完了不知道成不成」，也是唯一能让用户自己排除故障的地方。

### Step 4 · 生成第一张图（新增）

页面内直接调一次 `image.generate`：

- 默认模型：**最便宜的那个**（当前 qwen $0.01，而不是 flux $0.2）。
- prompt 预填一句可改的：`一只橘猫趴在窗台上晒太阳，午后暖光，写实摄影`。
- 按钮旁标注：**「本次消耗约 $0.01」**。
- 成功后：页面直接显示图片 + 一行字：

> 成功了。在客户端里这样说就行：**「帮我画一只橘猫，写实风格」**

这是整个方案的支点。**用户看过一次真实结果，比读十页文档都有效。**

可选优化：给每个新账号一次性的「试跑额度」（如 $0.05），首次试跑不计费。成本极低，但能把首次成功率拉到接近 100%。

### Step 5 · 三张意图卡片（新增）

不放「触发词大全」，放 3 张**场景卡**，每张一句可复制的话：

| 场景 | 复制这句话 | 结果 |
|---|---|---|
| 画图 | 帮我画一张 1:1 的图：雨后的东京街头，霓虹灯，电影感 | 同步返回 1 张图 |
| 改图 | 把这张图改成水彩风格 + 附上图片 URL | 图生图，返回 1 张 |
| 视频 | 用 happyhorse1.1 生成一段 5 秒视频：海浪拍打礁石，720P | 返回 task_id，需轮询 |

每张卡下面一行小字：用的哪个模型、大概多少钱、要等多久。**成本与等待时间必须写在卡上**，这是让用户敢点的关键。

## 6. 方案 C：低成本学习的机制

1. **渐进披露**：第一屏只讲「连上 + 出一张图」。视频、参考图、参数放在「已经成功过一次」之后再展开（可用 localStorage 标记）。
2. **场景优先于模型**：所有入口按「你想做什么」组织，不按模型组织。模型只在成本/速度有差别时才出现。
3. **失败自救**：错误码直接映射到一句中文动作（见 Step 3 的表），不要只抛英文原文。
4. **空状态即引导**：没有令牌时，页面不是空白，而是「创建令牌并试跑」一个按钮。

## 7. 验收指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 首次配置成功率 | 点过「测试连接」且 200 的会话占比 | > 80% |
| 首次出图率 | 配置后 24h 内至少一次 `image.generate` 成功 | > 60% |
| 首次配置耗时 | 打开页面 → 第一张图 | < 3 分钟 |
| `model` 留空比例 | 日志里 `param_snapshot` 无 model 的调用占比 | < 10% |
| 假成功工单 | 「Agent 说生成了但没图」 | 0 |
| 无效重试 | 402/401 后仍重试的次数 | 0 |

前两项现在没有埋点，需要先在页面加两个事件（`mcp_test_connection`、`mcp_first_generate`）。

## 9. 明确不做的事

1. **不做「触发词大全」**。MCP 不需要咒语，需要的是能表达清楚的意图模板。做大全等于承认用户要背命令。
2. **不做独立的 MCP 聊天页**。那是重造客户端，且用户真正的使用场景就在 Claude/Cursor 里。
3. **不给每个模型写教程**。教程随模型变化腐烂，应按「任务」组织（画图/改图/视频）。
4. **不追求「零误判」**。Agent 误判不可能归零。目标是「误判能被发现、能被恢复」——错误码 + `next_action` 比提高模型准确率更可控。

## 10. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| A1 改必填导致存量调用失败 | 高 | 先上 warning 版本，观察 2 周留空比例再切硬失败 |
| Step 4 的试跑产生真实费用 | 中 | 默认最便宜模型 + 页面明示金额；可选一次性额度 |
| `recommended_for` 靠人写，会腐烂 | 中 | 只写 3–4 个稳定标签，不做长描述；后续用日志成功率反过来校准 |
| 向导做成 5 步反而更长 | 中 | Step 1/2 已存在，实际新增只有「测试连接 + 试跑」两个动作，其余是文案 |
