## 8. 发现的问题（都不影响本次发布）

### P2 · schema 校验失败绕过了结构化错误

```
task.get 不传 task_id
→ isError:true, text="validating \"arguments\": validating root: required: missing properties: [\"task_id\"]"
→ 没有 structuredContent、没有 code

n 传字符串 "abc"
→ isError:true, text="validating \"arguments\": … type: abc has type \"string\", want one of \"null, integer\""
```

这是 SDK 在进 handler 之前就拦下了，`outputSchema` 声明了 `error{code,retryable}` 但这条路径拿不到，
且文案是 Go/英文。影响有限（agent 照着报错能改对），但这是**同一个服务端里第三套错误形态**。

可选做法：把 `task.get` 的 `task_id` 从 JS 层 `required` 里拿掉、在 handler 里判空；
`n` 不改类型，只在文档里说明这类错误来自 schema 层。都不算干净，建议**只记录不修**。

### ~~P2 · 重放在 structuredContent 里认不出来~~（2026-11-15 已修）

重放与首次生成的 `structuredContent` 完全一致（`status/model/outputs` 相同），
「未重复生成」只写在 text 前缀里。只读结构化字段的客户端会把它当成一次新生成。
修法：`generateOutput` 加 `replayed bool`（3 行）。已落地：重放结果带 `replayed: true`，
首次调用不带该字段。

### ~~P3 · 两条通道的 `n` 拒绝文案不一致~~（2026-11-15 已修）

顶层 `n=1000` → `n 最多 4，收到 1000；要更多请分多次调用`
`extra.n=1000` → `n 最多 4，收到 1000`（少了提示）

原因：`extra` 先被 `checkExtra → checkRange` 拦下，走不到 `checkBatchN` 的补充文案。
修法：`extra` 里的 `n` 在 `checkExtra` 之前先走 `checkBatchN`，两条通道共用同一句判定。

### P3 · 空能力列表也带了 5 分钟缓存

`resources/list` / `prompts/list` 现在返回 `ttlMs=300000, cacheScope=public`。当前无害
（永远是空），但将来真要加 `resources` 时，客户端可能把「空」缓存 5 分钟。

### 已知技术债 · 每次启动一条假 ERROR

```
[SYS] failed to migrate mcp protocols: Error 1054 (42S22): Unknown column 'protocol' in 'where clause'
```

`mcp_model_profiles.protocol` 列早已删除，迁移语句还在跑。修它要 +2 行 added、触顶合并预算，
上次已回退。不影响功能。

### 环境限制（不是服务端问题）

- 经 `127.0.0.1:8081`（mitm 反代）调 `subscriptions/listen`：**8 秒零字节**；
  直连 `apiduo.cn`：立刻收到 `notifications/subscriptions/acknowledged` 并保持打开。
  ⇒ 以后做推送必须把 `~/.workbuddy/mcp.json` 改成直连，或让反代不缓冲 SSE。

## 9. 结论

协议层（stateless、2026-07-28 握手、能力声明、缓存、限流）、工具层（结构化输出、错误分类、
幂等、并发保护）、真实链路（同步出图、异步出片、产物可达、计费次数）三块全部通过。

未覆盖：模型参数全枚举（只抽了 `duration`）、图生图 / 参考图、`n=2..4` 多图计费、
非默认模型（doubao / gpt-image / flux）。这些与本次改动的交集很小。
