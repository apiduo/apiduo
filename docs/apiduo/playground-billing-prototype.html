01为什么加这个

Playground 的用途是验证：这个模型能不能用、效果如何、贵不贵。现在只显示耗时，用户花完钱不知道花了多少，于是要么不敢用，要么月底看账单才发现。

把成本压到每一次请求上：金额贴在消息底部，和 token 数、首字延迟并列；想看怎么算的点开就是对账单。不需要去日志页翻。

02数据从哪来

  • GET /api/pricing → 模型倍率、组倍率、user_discount_ratios（组×模型）：给「发前预估」和价格条
  • stream_options.include_usage → 流末尾 usage：给「生成中」的 token 与预估金额
  • 响应头 X-Oneapi-Request-Id → GET /api/log/self?request_id=：拿到 quota、frt、other 里的倍率明细

三者对账后，金额标签从「约」变「已对账」，并附日志 id。

03对抗审查 · 会翻车的地方

  • 日志是异步落库的，请求刚结束不一定查得到 → 轮询上限 2s，超时降级为估算并明确标注，不冒充实际
  • 个人折扣覆盖组倍率而不是相乘 → 两个倍率都要显示，否则用户按乘法复算会发现对不上
  • 用户中途点停止 → 上游可能已产生 token，按已收到的 usage 结算，无 usage 才退回估算
  • 缓存命中单独列出，否则输入 token 对不上 prompt_tokens
实现前需确认：折扣规则含有效期，/api/pricing 已按当前时间展开，前端不要自行缓存超过一个会话。
