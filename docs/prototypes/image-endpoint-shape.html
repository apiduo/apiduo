单端点 / 双端点，到底在选什么

这套配置里最容易读错的一项是「上游布局」。它不是我们这边有几个接口， 而是上游的图生图怎么进——文生图两条路完全一样，差别只发生在带参考图的那一次请求上。

一机制：两条请求线，差在第二行

下面四个格子是后端 planSeedream / planGPTImage2 的真实分支，不是示意。

ARK 协议 单端点 Seedream 系
文生图
──▶ POST /v1/images/generations
application/json · 没有 image 字段
图生图
──▶ POST /v1/images/generations
application/json · image 内联（data URI 或 URL）
OpenAI 协议 双端点 gpt-image 系
文生图
──▶ POST /v1/images/generations
application/json · 没有 image 字段
图生图
──▶ POST /v1/images/edits 换路
multipart/form-data · image 落成文件，mask 也当文件
一句话：「单 / 双」说的是上游那边图生图有没有独立的门。 单端点 = 同一扇门，图片塞进 JSON；双端点 = 另开一扇门，图片当文件上传。 所以它天然只影响图生图——文生图在两种布局下都是一条 JSON。

① 只有名字，没有形状 「单端点」三个字要用户自己翻译成「图生图同路」。而这一层翻译，正是所有困惑的来源。
② 说明跟着选择被替换 选一个只显示一段话，两段永远看不到一起，所以「到底差在哪」只能靠记忆对比。
③ 从端点输入框凭空出现 选双端点后右侧多出「编辑路径覆盖」，没有交代它从哪来、留空会变成什么。

四方案 B：把选择挂到「上游」那一格上

既然它描述的是上游，就长在上游节点上。数据流里直接显示「1 个图片端点 / 2 个图片端点」， 点开才是选择——不用先展开「协议细节」才知道现在是什么形态。
