为什么用 MCP 接

模型能力写在服务端，客户端只负责传话。换模型不用改客户端配置。

能力自描述

模型有哪些参数、取什么值，models.list 直接告诉你，不用翻文档猜。

图片视频同一入口

令牌即权限

沿用你已有的令牌体系：额度、分组、IP 白名单全部生效，不新增一套凭据。

把你的 Agent 接到 apiduo

配好这一页，WorkBuddy、豆包工作、Trae、Cursor、Claude Code 里就能直接生成图片和视频。
全程只有一个必填项：你的令牌。

POST https://apiduo.cn/mcp Streamable HTTP 无状态 JSON 响应

→30 秒验证

先别急着改客户端配置。用一行 curl 确认令牌能通，能省掉后面一半的排查时间。

终端
$ curl -s https://apiduo.cn/mcp \
    -H "Authorization: Bearer sk-你的令牌" \
    -H "Content-Type: application/json" \
    -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

能看到 models.list / image.generate / video.generate / task.get 四个工具，就说明端点和令牌都对了。返回 401 请直接看第 1 步。

服务端是无状态的：不用先 initialize，也没有会话要维持。自己写客户端时，一次 POST 就是一次完整调用。

1准备令牌

MCP 用的是你调用 /v1 的同一套令牌，不需要单独申请任何东西。

令牌要能覆盖要用的模型。后台「令牌」页新建时，分组选 default；如果令牌设了模型限制，MCP 里也就只能用那几个模型。
后台 · 令牌新建令牌
名称cursor-agent · 随便取，方便日后吊销
分组default · 决定能用哪些模型
额度按需设置 · 生成类按次扣费，见下文
IP 白名单一般留空 · 一旦填了，只有白名单 IP 能调 MCP
令牌只显示一次。建完立刻复制，页面关掉就看不到了；丢了只能重建。

2配置客户端

选你正在用的那个：有界面的按路径点几下，没界面的贴一段 JSON。

国内常用
通用

办公助手走 WorkBuddy / 豆包工作，写代码走 Trae / CodeBuddy / Cursor；只支持 SSE 的客户端用 mcp-remote 桥一层。

~/.workbuddy/mcp.json　（项目级：<项目>/.workbuddy/mcp.json）
{
  "mcpServers": {
    "apiduo": {
      "type": "http",
      "url": "https://apiduo.cn/mcp",
      "headers": { "Authorization": "Bearer sk-你的令牌" }
    }
  }
}

入口：左侧「专家 · 技能 · 连接器」→「连接器」→ 右上角「自定义连接器」→「配置 MCP」，粘贴保存，回到列表点一次 信任——不点信任不会启用。

传输类型写 http；个别版本提示识别不了，就换成 streamablehttp 再试。

左侧「技能 · 连接器 · 伙伴」→「连接器」→ 右上角「新建」→「新建自定义连接器」，四个字段照填：

服务器名称apiduo
传输类型HTTP
服务器 URLhttps://apiduo.cn/mcp
自定义 HeadersAuthorization = Bearer sk-你的令牌 （Bearer 后有空格）

保存后回「我的技能 · 连接器」把开关打开。自定义连接器只在电脑版有，手机端和网页版看不到这一项。

验证：新建工作任务，说一句「用 apiduo 列出有哪些模型」。

灵码的 MCP 只有 SSE 和 STDIO 两种，没有填请求头的地方，所以用 mcp-remote 在本机桥一层（需要 Node 18+）：

先在本机跑通这一行
$ npx -y mcp-remote https://apiduo.cn/mcp \
    --header "Authorization: Bearer sk-你的令牌"

设置 → MCP 服务器 → 添加 → 类型选「可流式传输的 HTTP（streamableHttp）」：

名称apiduo
类型可流式传输的 HTTP（streamableHttp）
URLhttps://apiduo.cn/mcp
请求头Authorization=Bearer sk-你的令牌 （一行一对，Bearer 后有空格）

任何支持 Streamable HTTP 的客户端都能接，需要三个值：

URLhttps://apiduo.cn/mcp
请求头Authorization: Bearer sk-你的令牌
传输Streamable HTTP（POST，JSON 响应）
只支持 SSE 的客户端接不了。本服务不维持会话，一次请求一次响应；这类客户端用 npx -y mcp-remote <URL> --header "Authorization: Bearer sk-…" 在本地桥一层，通义灵码那一栏就是这套做法。

3确认接通

在客户端里说一句「列出 apiduo 有哪些模型」。它会调 models.list，正常返回长这样：

models.list · 返回摘要
{
  "models": [{
    "id": "flux-3-image",
    "kind": "image",
    "input": { "max_reference_images": 10 },
    "parameters": {
      "aspect_ratio": { "enum": ["1:1","4:3","16:9","auto"] },
      "resolution": { "enum": ["768sq","1k","1.5k","2k"] },
      "n": { "min": 1, "max": 4 }
    },
    "summary": "FLUX 3 文生图 / 图生图：最多 10 张参考图…"
  }]
}
列表为空不等于没接通。它表示管理员还没在「MCP 能力注册」里启用任何模型。此时工具在、模型不在。

4工具清单

四个工具，覆盖「先查再生成、异步再查回」的完整链路。参数取值以 models.list 返回的 parameters 为准，不要臆造。

工具作用关键参数
models.list列出已启用模型与能力：类型、执行方式、输入上限、参数枚举kind（image / video）
image.generate文生图；传 reference_images 即图生图，模式自动推导prompt · model · size · n · reference_images
video.generate文生视频 / 图生视频；多数模型异步，立即返回 task_idprompt · model · duration · reference_images
task.get查询异步任务；working 时按 poll_after_ms 再查task_id

5计费与限制

计费与直接调 /v1 完全一致，按所选模型的单价扣额度
限流令牌级限流照旧生效，MCP 不额外放宽
异步任务task_id 自带签名，任何副本都能查，不需要粘性会话
失败重试status=failed 时不要用同样参数重试，先看错误原因

?常见问题

401返回 401，令牌明明是对的

按顺序排三个：令牌是不是被停用了；是不是复制时带了空格或换行；请求头有没有写 Bearer 前缀。

还有一种：令牌设了 IP 白名单，而你当前的出口 IP 不在里面。这种情况返回的是 403，不是 401，注意区分。

405客户端日志里 GET /mcp 报 405

正常现象。这个端点不支持 SSE 长连接，只接受 POST。部分客户端会先 GET 一次探测，失败后自己回落到 POST，工具照样能用。

如果客户端因此直接判定服务器不可用，说明它只支持 SSE 传输，换支持 Streamable HTTP 的客户端。

0工具能看到，但模型列表是空的

说明端点通了、令牌也通了，只是后台还没有启用任何模型声明。让管理员到「MCP 能力注册」里启用一个，或在新建模型时勾上「启用」。

?生成了图，但返回的是一长串 base64

正常。有些上游不回图片 URL，只回 b64_json，服务端原样透传，客户端一般能直接渲染。要落地成文件，自己解一下 base64 即可。

轮视频一直 working，要不要重试

不要。按返回里的 poll_after_ms 间隔继续查同一个 task_id。重新发起会再扣一次费用，而且和原来的任务没有关系。
