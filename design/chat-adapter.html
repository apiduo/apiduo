Model identity isolation / chat modality

客户端只知道标签，
上游真名只活在网关里。

模型重定向是两段式：请求改名 + 响应归名。只做一半，客户端读一次响应就知道上游是谁。 本产品把「模型名」从传输事实降级为标签，并在出站字节上保证这一点 —— 不靠约定，不靠全文替换。

客户端

model: acme-pro
只认识标签，不认识上游

──▶

chat-adapter

映射 · 凭据重注入 · 逐字段归名 · 头白名单
唯一知道真名的进程，无状态

──▶

上游

deepseek-v4-flash-260425
只看到真名与客户端凭据

G1

请求面不出现上游名

唯一改写点是映射层；未命中即 400（strict 默认开）。

G2

响应面全量归名

model / 指纹 / 错误 / 头，全部落在对外名命名空间。

G3

失败面不泄漏

错误文案默认泛化；无法脱敏时拒绝转发，不静默直通。

N1

模型身份不可保证

内容自述与行为指纹属推断层，任何网关都消不掉。这条写在第一屏。

04 / ACCEPTANCE

05 / SCOPE

        
做什么，不做什么

      

      
边界写清楚，比能力列表更重要。

    

    

      

        
只做三件事

        
请求改名、响应归名、出站面收敛。canonical 就是入站协议本身 —— 不做协议转换，vendor extras 一律透传。

      

      

        
无状态，无管理台

        
配置进 Git，改配置走发布。在线改配置会引入第二份真相，灰度与回滚都要重做。

      

      

        
明确不做

        
负载均衡、准入鉴权、计费、模型能力矩阵、客户端可选上游地址（SSRF 面）。
