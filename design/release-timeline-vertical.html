垂直时间轴 · 设计说明

同一份发布数据，换方向不是换皮，是换了一套取舍。

1. 垂直换来了什么

维度水平鱼骨垂直时间轴
节点容量4–6 个，再多主脊会挤8–12 个，纵向可续
单条文案短，约 8–12 字长，约 18–24 字
一眼看完能，适合投影不能，需要滚动
阅读方向左 → 右上 → 下（中文习惯）
「现在在哪」竖直参考线，不显眼整条横线，最显眼

这一版放了 6 个阶段。同样的 6 个节点塞进水平鱼骨，主脊宽度要 1400px 以上， 投影时会缩到看不清 —— 这是垂直版存在的实际理由。

2. 左右分栏替代上下分扇

垂直后，上下扇变成左右栏，语义反而更直白：

  • 左侧 = 内部动作：切分支、灰度放量、指标对齐
  • 右侧 = 对外影响：谁能看见、要不要改代码、能不能回退

外部读者可以整列跳过左边。这比水平版的「只看下半张图」更容易执行 —— 水平时眼睛要上下扫，垂直时只需读一列。

3. 「现在」是一条横线

垂直时间轴里，当前时刻用一条贯穿左右的横线表达，配合滑块上下移动。 这比水平版的竖线更醒目，因为横线切断了整张图，视觉上无法忽略。

横线之上的节点实心、之下空心 —— 不用读文字就能知道走到哪了。 发布当天读者只关心这一件事。

4. 骨为什么要斜向下

垂直版最容易画错的地方：把子项水平列在主脊两侧，结果变成「时间轴 + 目录」，失去鱼骨的发散感。

这里让骨从节点先水平外移 26px，再以 45° 斜向下 125px。斜向下而不是向上， 是因为每个节点占据的是「它自己到下一个节点之间」的空间；向上会侵占上一个节点的区域。

5. 什么时候用哪一版

水平鱼骨：变更项少（≤4）、需要投影或嵌在大屏里、要一眼看完。
垂直时间轴：阶段多（≥5）、文案长、读者在手机上或滚动阅读、需要强调「现在」。
不要两版都上。同一份发布同时提供两种视图，读者会怀疑数据不一致。 选一种，用 ?t= 这类参数控制阶段，不要用两套版式。

6. 落地方式

和鱼骨版共用同一份结构化数据：

{ version, phases:[{t, at, actions[], impacts[], breaking[]}] }

两个渲染器读同一个对象，样式层各自处理。不要为垂直版单独维护一份内容 —— 那必然漂移，最后图上和清单上说的是两件事。
