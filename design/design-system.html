01色彩

11 个值，只有 1 个强调色。对比度按 WCAG 2.1 相对亮度实算，底色取 --paper。低于 4.5:1 的值只允许出现在非文字元素上。

02字体

四档，相邻比 1.17 / 1.29 / 1.33。12px 是可读下限，不得再小；数字一律等宽对齐。

03间距

4 基数。同组元素 4–8，不同组 16 以上；标题上方空间必须大于下方。

04动效

只动 transform 与 opacity。退场快于进场；按压要有位移，只有变色等于没反馈。点右侧重放。

不该动的四件事：数字滚动计数、表格逐行入场、图表线条绘制、任何循环动画。 它们都在「每次刷新都动」，对读数只有干扰。

06禁止清单

三套规范的交集。这些不是审美偏好，改动前需要理由。

禁止为什么
hero-metric 模板大数字 + 小标签 + 三四个支撑统计 + 强调色，是模型做看板的默认解。它让页面看起来有重点，却没回答「谁在坏」。
eyebrow / kicker标题上方那行小字加圆点，除了显得「设计过」不承载信息。
左侧 3px 竖条强调条是最典型的模板痕迹；用背景色或边框整体表达。
卡片与投影卡片意味着「可以拿走的一块内容」。这里是连续的时间序列与长表，容器化会切断阅读流。
颜色单独表意色盲用户读不到。错误码必须带层级文字，渠道状态必须写「自动禁用」。
未主题化的浏览器表面选区、光标、滚动条、焦点环带着浏览器默认值，是「没做完」最明显的信号。

07五个版本

同一份数据与交互，五种设计语言。违规数是 impeccable detect 的实测结果，不是估计。

版本主张违规代价
v2 判断版 基线带 + 错误聚类 + 变更标记 + 四态外的新状态 0 同一条数据链路上补判断能力，未接入真实接口
v1 克制版 状态句 + 刻度尺，零卡片 0 信息密度最低的那一档里最克制
Hallmark ASCII 字符场 + 钴蓝，单一强信号 0 首屏用了 hero 数字，与当前版的主张相反
Material 3 完整 M3 组件规范 2 密度比控制台版低约 25%
控制台版 信息密度最高，适合长时间扫读 31 11px 正文在高分屏上不可读

08验收

四条命令，缺一条都不算通过。

npx impeccable detect design/error-dashboard-impeccable.html   # 期望 EXIT=0
node --check /tmp/imp.js                                      # 内联脚本语法
npx dembrandt http://127.0.0.1:8791/... --json-only           # 反抽令牌比对
# 1440 / 1024 / 390 三档 + 键盘：行可聚焦、Enter 下钻、Esc 关面板、焦点归还
抽取器的两个坑：它只读 当前已渲染 的 DOM，隐藏 tab 里的控件看不见； 未设 transition 的元素，缓动计算值就是初始的 ease，会被误报成「用了默认曲线」。

这一页自己遵守它描述的规则：方角、hairline、零卡片、12/14/18/24 四档字号、4 基数间距。 所有色值与间距在运行时从 :root 读取，改样式表即改本页，不存在第二份真相。
