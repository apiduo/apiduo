业内现在长什么样 · 六种做法

Linear视觉标杆
每周 changelog 当杂志文章写：满幅产品截图 + 动图 + 编辑口吻。 动效只用 GIF 展示功能本身，页面本身不炫技。2026 年最常被抄的一家。
StripeAPI 场景
每条变更固定五段：描述 / 旧行为 / 新行为 / 迁移步骤 / 受影响端点。 零动效，纪律即产品。做网关、做 API 的产品应该先抄这个，再谈视觉。
Figma / Vercel带证据
Figma 每条配注释过的 UI 图；Vercel 每条带作者头像和署名。 「谁改的 + 改成什么样」比动效更能建立可信度。
by.U（Telkomsel）动效范例
更新弹窗用 Lottie 角色动画：入场 1.5s 带过冲，之后转挥手/眨眼的轻柔循环。 结论是「循环要轻，不然会烦」—— 和我上面 07 的判断一致。
Supabase活动型
Launch Week 把五天的发布做成一个事件页，倒计时、逐日解锁、卡片翻转。 它炫的是「事件」，不是「公告」—— 一年只有四次。
Notion / Raycast克制
Notion 用 emoji 标题 + 大白话；Raycast 纯 Markdown 三段式。 这俩证明：公告的竞争力在内容和节奏，不在动效。

落到 apiduo：哪几招能用

直接用

  • 03 未读呼吸 —— 铃铛角标，状态型，不衰减
  • 08 确认收束 —— 「我知道了」必须有反馈
  • 01 横幅滑入 —— 只在紧急公告且首次出现时
  • 06 滚动揭示 —— 发布公告长清单，只播一次

挑场合

  • 02 列表错开 —— 只在首屏，超过 5 条改成立即显示
  • 04 数字滚动 —— 只在首次加载，刷新不重播
  • 05 流彩背景 —— 只给发布公告详情页头部，面板里绝对不用

别用在公告上

  • 光标跟随光斑 —— 用户在工作，不在逛展
  • 逐字打字机 —— 公告不是聊天，等待没有意义
  • 3D 翻转卡片 —— 翻过来还是同一段文字
  • 循环粒子背景 —— 抢走正文可读性，且烧 GPU
  • 自动播放视频 —— 控制台里突然出声是事故

一条硬规则

动效只能编码「状态发生了变化」，不能编码「这里有个东西」。
「有新公告了」是状态变化 → 动。
「这是一条公告」不是状态变化 → 不动。
按这条筛，上面 8 种里只剩 03、08、以及首次出现的 01 —— 其余的都要有触发条件。
