公告大屏 · 设计说明

对象：挂在运维区/前台的 55–75 寸屏，无人值守，只读。

1. 与大屏无关的三件事，先砍掉

  • 不能有交互。没有鼠标键盘，hover / 点击 / 滚动全部作废。所有信息必须自动呈现，交互退化为「轮播 + 停留」。
  • 不能有内部数据。已读率、未确认人数、渠道名一律不上墙。屏幕在公共区域，等于对外发布。
  • 不能沿用控制台字号。12px 在 3 米外等于不存在。字号由视距决定，不由设计稿决定。

2. 字号来自视距，不是审美

元素字号55″ / 3m 视角75″ / 5m 视角
主标题76px约 33′约 20′
正文34px约 15′约 9′
队列标题28px约 12′约 7′
元信息下限20px约 9′约 5′

可读下限约 5′（弧分）。20px 是这套版式里最小的一档，再小的信息就不该上墙 —— 让它留在控制台。

3. 轮播规则

  • 停留时长 = max(10s, 字数 ÷ 11)，上限 22s。按中文阅读速度 300 字/分反推。
  • 底部 2px 进度条是唯一的「还有多久」信号，不显示数字倒计时（数字会让人盯着等）。
  • 只有一条时不轮播、进度条隐藏 —— 否则进度条在说谎。
  • 紧急级别不参与轮播：钉在主位直到过期或下线，同时拉起顶部红条。

4. 六个状态

状态屏幕上是什么
常态主公告 + 右侧队列 + 轮播
紧急顶部红条 + 主位钉住，队列仍显示
无公告大时钟 + 「当前无公告」。不留空白，也不放占位文案
取数失败保留上一次内容 + 角标「数据停在 00:12」。绝不切空白页
未授权配置码 + 重新绑定指引。不能跳登录页 —— 现场没人能登
复合版式右侧队列换运营指标，见下方取舍

5. 字段扩展

  • placements 增加 screen，与 banner / dashboard / popover / login 同级。
  • 大屏路由 /display/announcements?k=<screen_key>，只读 key，可随时吊销，不需要用户会话。
  • cta_url 在大屏上渲染成二维码，不渲染按钮。按钮在大屏上永远点不到。
  • 正文建议 ≤ 120 字（三行内）。编辑器里勾了 screen 的公告超过 120 字标黄提示 —— 大屏不是读长文的地方，超出的部分读者看不到。
  • 有效期沿用 starts_at / ends_at 派生：定时公告到点自动出现，过期自动消失，大屏不需要人管。这是上一轮状态机唯一能兑现价值的地方。
纯公告大屏会空转。按现有频率（月均 8–10 条、每条 3–7 天），一块 7×24 挂着的屏， 约 85%–90% 的时间显示的是「当前无公告」。屏幕不会坏，但没人会再看它第二眼。
建议。如果屏是长期挂着的，用第 6 个场景的复合版式：公告仍占主位（左侧 1200px）， 右侧队列换成本周请求量 / 成功率 / 当前故障数。公告为空时，右侧指标仍在工作，屏不空转。 如果只在发公告时临时点亮，纯公告版式即可。

6. 没做的事

  • 不做触摸翻页：屏前有人时，翻页的人会把内容停在自己想看的那条，后面的人看不到。
  • 不做声音提示：无人值守的屏突然响，是事故不是特性。
  • 不做像素位移防烧屏：原型不演示。落地时按每 30 分钟位移 2px 实现，且位移只作用于整体容器。
  • 不做「已读/确认」统计上墙：属于内部数据。

7. 验收

  • 3 米外能读出主标题与「是否仍在生效」，读不出元信息即失败。
  • 拔网线 5 分钟，屏上必须还有内容，并标注停更时间。
  • 连续 7 天无公告，屏不得出现空白区域。
  • 灰度（filter:grayscale(1)）下级别仍可区分 —— 级别同时有文字与色带，不只靠颜色。
