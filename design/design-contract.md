# 错误看板 · 设计契约

这份文档回答一个问题：**别人要照着做一个一样的界面，需要被告知哪些事。**
不是风格说明，是可以被检查的规则。凡带「必须」「不得」的条目，改动前需要理由。

对应实现：`error-dashboard-impeccable.html`
令牌来源：`tokens.json`（与 CSS `:root` 一一对应，改一处必须改两处）

---

## 1. 这套界面在做什么

给平台运维在故障发生时**判断三件事**：现在坏没坏、坏在哪一层、要不要动手。

因此结构只有一段话、一根刻度、两张表。没有 KPI 卡、没有仪表盘、没有环形图 ——
KPI 卡墙是这类页面最常见的形态，也是最没信息量的形态：四个数字并排，读者仍不知道
「谁在坏」。

---

## 2. 材质：纸、墨、一根线

| 元素 | 值 | 规则 |
|---|---|---|
| 底 | `#fcfcfa` | 暖白。纯白 `#fff` 在长时间盯屏时发刺 |
| 墨 | `#1a1c1e` | 带蓝的深灰，与暖白形成冷热差 |
| 分隔 | `#e4e4de` | **1px，唯一的层级手段** |

**不得**使用：卡片容器、投影、圆角面板、渐变背景、毛玻璃。
区块之间只靠一条横线分隔；层级靠位置和字号，不靠容器。

> 这条最容易在迭代中失守。一旦给某块加了白底圆角卡片，整页的"报表感"就回来了。

---

## 3. 色彩：7 个值，其中只有 1 个强调色

| 令牌 | 值 | 角色 | 允许出现的位置 |
|---|---|---|---|
| `paper` | `#fcfcfa` | 底 | 全局 |
| `paper-2` | `#f4f4f1` | 次级表面 | 行 hover、代码底 |
| `rule` | `#e4e4de` | 分隔线 | 区块之间 |
| `rule-2` | `#cfcfc7` | 强分隔 | 表格底线、面板边、控件描边 |
| `ink` | `#1a1c1e` | 正文 | 数字、错误码 |
| `ink-2` | `#45484b` | 次级正文 | 状态句、表格正文 |
| `muted` | `#6b7076` | 标签 | 图注、表头、说明（对比度 4.9:1，是全站最浅的可读文字） |
| `accent` | `#9a3412` | 异常 | 峰值、故障时段、主错误码 |
| `ok` | `#3f6f4a` | 成功 | 仅重试阶梯与链路成功节点 |
| `err` | `#a4161a` | 坏了 | 取数失败、脚本异常 |

**规则**

- `accent` 全局出现次数应 **少于 20 处**。它是"值得看一眼"，不是装饰。
- `accent` 与 `err` 不混用：前者是异常，后者是故障。
- **颜色不得单独承载语义**。错误码必须带层级文字（渠道/上游/请求），
  渠道状态必须写「自动禁用」而不是只给红点。

---

## 4. 字号：4 档，相邻比 ≥ 1.17

| 档 | 值 | 用途 |
|---|---|---|
| `label` | 12px | 标签、图注、表头 |
| `body` | 14px | 正文、表格、状态句 |
| `section` | 18px | 区块标题、首屏主句 |
| `display` | 24px | 保留，当前未用 |

**不得**低于 12px。11px 正文在 2x 屏上就是看不清 —— 这是被工具判为可读性失败的门槛，
不是审美偏好。

**数字一律 `font-variant-numeric: tabular-nums`**，否则列对不齐；错误码一律等宽字体。

---

## 5. 间距：4 基数，紧分组松分隔

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`

- 同组元素之间用 4–8；不同组用 16 以上。
- **标题上方空间必须大于下方**，否则标题会贴住下面的内容、远离上面的内容。
- 不允许出现 `13px`、`18px` 这类非基数间距。需要更细时用 4 的倍数缩放，不要新造数值。

---

## 6. 形状：方角是决定，不是遗漏

全站 `border-radius: 0`，唯一例外是刻度柱顶部的 1px（避免像素阶梯）。

理由：圆角在大众认知里等于"卡片"，而卡片意味着"可以拿走的一块内容"。
这里是连续的时间序列和长表，容器化会切断阅读流。

---

## 7. 动效：三个时长，三件事

| 场景 | 时长 | 曲线 |
|---|---|---|
| 行 hover / 颜色 | 90ms | `linear` |
| 按压 | 160ms | `cubic-bezier(0.4,0,0.2,1)` |
| 面板退场 | 180ms | 同上 |
| 面板进场 / 视图淡入 | 260ms | `cubic-bezier(0.22,1,0.36,1)` |

**必须**

- 退场快于进场。撤掉一个东西时用户已经决定了，不该再等。
- 按压要有位移（`scale(0.972)`），只有变色等于没反馈。
- 只动 `opacity` 与 `transform`，不动 `width`/`height`/`top`/`left`。
- `prefers-reduced-motion` 下全部关闭。

**不得**

- 数字滚动计数、表格逐行入场、图表线条绘制、任何循环动画。
  这四件都在"每次刷新都动"，对读数只有干扰。
- `transition: all`。

---

## 8. 状态：四种，缺一不可

看板最容易漏的不是好看的常态，是接口挂了显示什么。

| 状态 | 要求 |
|---|---|
| **加载中** | 延迟 180ms 才出骨架（快请求不闪）；出现后至少留 320ms。骨架的**行高与列数必须和最终内容一致**，否则数据到了整页跳 |
| **取数失败** | 保留上一次结果并**明确标注可能过期**，给出重试按钮。不得留空表格 |
| **区间无数据** | 说"全部成功"，而不是"0 次失败，没有单一来源占主导"。刻度区给一句话，不留空白 |
| **筛选无结果** | 给出"清除筛选"这个下一步，不留死路 |

顶栏状态句与内容必须一致：加载中时顶栏也要变成"正在读取日志…"，
不能还挂着上一次的结论。

---

## 9. 禁止清单（三套规范的交集）

- 首屏 hero-metric 模板：大数字 + 小标签 + 三四个支撑统计 + 强调色
- eyebrow / kicker 小字（标题上方的小圆点加字母那种）
- 左侧 3px 强调竖条、嵌套卡片、渐变文字
- 装饰性状态圆点（用文字表达状态）
- 用 unicode 当图标、用等宽字体当"技术感"道具
- 用 sparkline 替代本该展示的内容
- 未主题化的浏览器表面：文本选区、光标、滚动条、焦点环

## 10. 验收

```bash
# 1. 规则检查（62 条确定性规则，无 LLM）
npx impeccable detect design/error-dashboard-impeccable.html   # 期望 EXIT=0

# 2. 灰度验证（结构不靠颜色成立）
#    浏览器控制台：document.documentElement.style.filter = 'grayscale(1)'

# 3. 令牌一致性（反向抽取，与 tokens.json 比对）
npx dembrandt http://127.0.0.1:8791/error-dashboard-impeccable.html --json-only

# 4. 三档视口 + 键盘路径
#    1440 / 1024 / 390，行可聚焦、Enter 下钻、Esc 关面板、焦点归还
```

**注意**：`dembrandt` 只抽取**当前已渲染**的 DOM。隐藏 tab 里的控件它看不见 ——
抽 `inputs: {}` 时先确认那一屏是不是 `hidden`。

## 11. 已知偏离

- **`h1` 比 `h2` 小**（14px vs 18px）。这是报头式布局：页面名在左上角作为定位，
  区块标题才是阅读层级。语义层级正确，视觉层级由位置承担。
- **390px 下刻度柱压缩到 3px 一根**。24 小时的 144 个桶挤进 390px 只能这样；
  强行加宽会让时间轴断成两行。属于数据密度问题，不是渲染失败。
