03

能力边界：拒绝、降级、丢弃

每条都有「为什么」
输入 / 情况结果为什么
n = 2 及以上400 param: n一次 :generateContent 只产出一张最终图。扇出 N 次要回答「部分成功怎么计费、怎么退、怎么拼 data[]」，同步入口没有承载者。
stream: true忽略 同步返回图片主端点的回包形态是完整 JSON。要流式就得接 :streamGenerateContent，那是另一种传输，不在本次范围。
/v1/responses 入口接管 本次补折叠复用 ResponsesRequestToChatCompletionsRequest，回包复用 ConvertResponse。不手写 SSE，否则下一次协议变更必漂移。
:generateContent 未声明路由503渠道选择器只认已声明的路由；图片协议不替运维放行 Gemini 的通用入口。
:generateContent 已声明，但模型不在 imagine 名单不接管 原生链路防止同渠道混挂文本模型时把一次对话折叠成出图。
mask丢弃 记日志Gemini 没有 mask 参数。透传会 400；静默转发会让用户以为蒙版生效。
seed / style / quality / negative_prompt丢弃 记日志上游无对应字段。写入 other.dropped_params，排查时能看到「用户传了但没生效」。
image_size = 8K400只接受 1K / 2K / 4K。不把未知值静默降成 2K，否则用户按 8K 付费买 2K。
size = 999x999上游默认像素无法唯一映射宽高比。只映射五个确定档，其余不猜。
finishReason = SAFETY400 content_policy_violation上游拒画，不是网关故障。不能落 500，也不能重试——重试只会再被拒一次。
要 url 但渠道没配存储200 b64_json契约 §2.2 已允许：上游给 b64 就照实回 b64。网关不替上游兜底转存，没有存储时那只会变成 502。
4K 图的 base64 超过 16 MiB502旧上限对 4K 不够。gemini 分支单独给 64 MiB，超限明确失败，不截断。
04

出口净化：不暴露上游

五条规则，按客户端能看到的东西排列
面处理为什么
响应体按入口白名单重建解析失败返回 502，不原样透传——否则 candidates[] 会直接给 OpenAI 客户端。
模型名回包写请求名写上游名会在模型重定向后暴露真实模型。
错误码表 + 固定英文上游 message 常带 models/xxx 与域名；真实原因只进管理端日志。
响应头白名单Server、X-Goog-*、Set-Cookie 全是身份。
图片 URL非本域必须转存，否则降级 b64链接 host 就是上游（*.volces.com、storage.googleapis.com）。
T3 · 不可区分性

同一个请求分别打 ark / openai / gemini，响应的字段集合、响应头集合、错误码必须完全相同；差异只允许出现在 b64_json 与耗时。字段集合用反射比较，不做字符串包含。

05

不变量：五入口、三上游、一个 canonical

I1

入口只决定「怎么读请求、怎么回包」。Gemini 的差别在上游报文，不在客户端契约，所以不加前门。

I2

主端点仍是唯一地址。模板里只有一个变量 {model}，它来自请求，不是第二个配置。

I3

生图与编辑是同一端点、同一脚本。图生图只是多传一个 inlineData part，没有第二遍改写。
