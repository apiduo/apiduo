取舍对照

四个维度：占不占布局、遮不遮内容、展开成本、移动端成本。

方案宽度定位占据布局展开成本风险
A · 居中窄卡 ≤ 680px，居中 流内，推内容 42px（含上下留白约 66px） 卡片内部生长，max-h 232 滚动 比通栏多占两侧留白；极窄屏会退化成通栏
B · 右上浮卡 336px 固定 absolute / fixed 0 卡片内部生长 盖住页面右上操作区；移动端必须改底部抽屉
C · 胶囊条 fit-content 流内居中 34px 需要 popover 或 dialog 长标题必须截断；多一层弹层，焦点管理复杂
  • 推荐 A 的理由：项目现有约束是「推内容不遮内容」（authenticated-layout.tsx 注释已写明），A 是唯一同时满足「窄」和这条约束的形态。
  • 不推荐 B：内容区右上角是通知铃铛与头像的位置，浮卡会长期压住可点区域；且 fixed 在侧栏折叠、滚动容器里都要额外处理。
  • C 的问题不在视觉：胶囊很好看，但要让 3 条以上可读，就必须引入 popover —— 一个「横幅」不值得为它增加一层浮层和 focus 管理。
